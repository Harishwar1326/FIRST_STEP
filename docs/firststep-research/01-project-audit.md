# Deliverable 1 - FirstStep Project Audit

**Audit date:** 2026-10-11  
**Evidence scope:** repository source, configuration, checked-in dataset/model artifacts, documentation, and reproducible local commands. No live database, deployed service, real student telemetry, or user study was available.

## Executive finding

FirstStep is an implemented React, Express, MongoDB/PostgreSQL, and FastAPI platform with substantial feature breadth. The strongest verified implementation is the Smart Notes workflow, backend-persisted learning and administration data, and programming-lesson video telemetry. The platform also contains four independently trained scikit-learn models. Artifact-backed inference follows the training feature order, while emergency in-memory retention and style fallback models use different feature meanings. Several AI-service modules are prototypes or fallback layers: they use in-memory state, fixed synthetic graphs, random initialization, hard-coded recommendations, or external LLMs rather than a validated adaptive learner model.

The README is useful as an intended architecture description, but it overstates offline support, Redis session/caching, WebSocket use, graph generation from notes, and the operational completeness of the AI service. The classifications below are based on code paths, not marketing text.

## FastAPI endpoint inventory

`GET /health`; document/flashcard/mindmap/question pipelines; twin initialize, analytics, recommendations, progress; academy plan, review, due cards, streak, and technique recommendation; forest graph, path, gaps, and concept details; thinking challenge, answer, history, and score; learning profile prediction and content generation. Exact paths are defined in [ai_service/main.py](../../ai_service/main.py) and its router modules.

## Persistence inventory

- **PostgreSQL:** active authentication store. `users` contains id, name, email, password hash, role, level, points, activity timestamps.
- **MongoDB:** application documents including notes, lessons, quizzes, tasks, learning profiles, analytics, revisions, recommendations, twin records, forest graphs, academy records, assessment profiles, programming progress, thinking activity, and admin logs.
- **Redis:** connection is established, but meaningful cache/session use was not demonstrated.
- **Chroma:** document embeddings/indexing path exists, with local and cloud configuration variants.
- **Browser storage:** JWT, theme, and guest/session identifiers; no offline data store.

## Verification checks

- Frontend: `Set-Location frontend; npm run build` passed on 2026-10-11; Vite emitted a large-chunk warning.
- Backend: `Set-Location backend; npm test` exits zero but only prints `Error: no test specified`; it is not a real test suite.
- AI service: `python -m pytest` collected zero tests and exited with code 1.
- ML training: completed successfully; measured results are documented in [03-ai-ml-audit.md](03-ai-ml-audit.md).

## Important implementation risks

1. FastAPI has permissive CORS and no authentication middleware.
2. Several guest/AI routes accept caller-supplied identifiers.
3. JWTs are stored in browser `localStorage`, increasing exposure to XSS.
4. `render.yaml` contains a real-looking MongoDB credential and must be treated as compromised.
5. `pytesseract` is imported but absent from Python requirements, and the Docker image lacks the Tesseract binary.
6. Docker Compose does not pass external AI credentials, so fallback behavior is likely in that environment.
7. Python Twin, Academy, Forest, and Thinking state is process-local.
8. Runtime inference features do not fully match the features used to train the serialized models.
9. No meaningful automated test suite was found.
